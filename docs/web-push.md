# Web Push notifications

GigWithMe sends gig notifications over **web push** as a third channel alongside
SMS (Twilio) and email (Mailgun). The goal: engaged members get free, instant,
actionable alerts, and the Twilio bill tapers off — without anyone being forced
to log in.

## Channel selection

`App\Notifications\Concerns\RoutesGigNotification::via()` picks channels per
member:

- **web push** when the member has an active push subscription — it *supplants*
  SMS;
- otherwise **SMS** when they have a phone number;
- plus **email** whenever they have an address (alongside push or SMS).

So a subscribed member gets push + email; an unsubscribed one is unchanged
(SMS + email). The three gig notifications (`GigConfirmed`, `GigPollOpened`,
`GigPollNeedsAttention`) each implement `toWebPush()` next to their existing
`toTwilio()` / `toMail()`.

`GigPollOpened` carries **"I'm in" / "Can't make it" actions** — the service
worker records the reply via the token-authorized `/rsvp/{token}/reply` endpoint
straight from the notification, no app open.

## Login-free opt-in: the durable push token

Ordinary members never log in — today they're identified by per-gig RSVP tokens.
Push keeps that model via a **durable per-member token** (`users.push_token`,
minted lazily by `User::ensurePushToken()`):

- the RSVP page (`/rsvp/{token}`) passes the member's `push_token` to the opt-in
  UI, so subscribing ties the browser's subscription to the member with no
  session;
- `/m/{push_token}` is the member's login-free personal home (upcoming gigs +
  push toggle).

Subscriptions are stored by `laravel-notification-channels/webpush`
(`push_subscriptions` table, `HasPushSubscriptions` trait on `User`).
`PushSubscriptionController` exposes token endpoints (`/push/subscribe/{token}`)
for members and session endpoints (`/push/subscribe`) for logged-in
owners/admins.

## iOS

iOS Safari only delivers web push to an **installed PWA**, and that install has a
storage sandbox separate from Safari. The only inbound identity channel is the
manifest's `start_url`, so `ManifestController::member()` serves a personalized
manifest at `/m/{push_token}/manifest.webmanifest` with
`start_url: /m/{push_token}`. The member-home page links it, so the installed app
relaunches already identified and can enable push without a login. `PushOptIn.vue`
detects iOS-Safari-not-installed and shows an "Add to Home Screen" hint instead
of a toggle that can't work yet.

## Pieces

- Service worker: `public/sw.js` (push + notificationclick, registered in
  `resources/js/app.js`).
- Composable: `resources/js/composables/usePushNotifications.js`.
- UI: `resources/js/components/PushOptIn.vue` (used on the RSVP page, member home,
  and settings → Notifications).
- VAPID keys live in `.env` (`VAPID_*`, generated by `php artisan webpush:vapid`),
  surfaced to the client as the shared `webpushKey` Inertia prop.
- Icons: `public/icons/` (generated; Pacific Cyan brand mark).

## Caveats

- iOS push needs iOS 16.4+ and the member actually installing the PWA — adoption
  is the soft spot. SMS stays the fallback for anyone unsubscribed, so no member
  goes dark.
- The gig notifications are `ShouldQueue`; web push delivery needs a running
  queue worker in production.
